# Frontend v6

Vue 3, Vite, Pinia, Bootstrap 5 e bootstrap-vue-next, em `_frontend/v6/`. É o destino do código
novo. O Django entrega `_templates/v6/base_v6.html` em `/v6/<slug>`, e o Vue Router assume daí.

## Estrutura de `src/`

| Caminho | Conteúdo |
| --- | --- |
| `main.js`, `App.vue` | Inicialização, plugins e `provide('EventBus')` |
| `registerComponents.js` | Componentes globais, carregados de forma assíncrona |
| `routers/index.js` | Rotas, com módulos em lazy import |
| `modules/` | `root`, `loa`, `sessao`, `chat`, `arq`, `painelset`, `messages` |
| `components/` | `atoms`, `selects`, `utils` e componentes compartilhados |
| `stores/` | `SyncStore`, `AuthStore`, `TeleportStore` |
| `utils/` | `resources`, `ws`, `timer`, `EventBus.js` e outros |
| `composables/` | `WsTimeRefresh.js` |

## Componentes novos

Use `<script setup>` e organize o script nesta ordem:

```vue
<script setup>
// 1. Imports
// 2. Composables
// 3. Props & Emits
// 4. State & Refs
// 5. Computed Properties
// 6. Watchers
// 7. Events & Lifecycle Hooks
// 8. Functions
</script>
```

A ordem vale apenas para componentes novos. A maioria dos existentes não a segue e **não deve ser
reordenada**, a menos que seja dito explicitamente no prompt ou SKILLS. `modules/root/SideLeft.vue` é um exemplo que a adota.

Os componentes do bootstrap-vue-next são resolvidos automaticamente pelo Vite, sem import.

## Imports e globais

```js
import { useSyncStore } from '~@/stores/SyncStore'
import { useAuthStore } from '~@/stores/AuthStore'
import { useMessageStore } from '~@/modules/messages/store/MessageStore'
import Resources from '~@/utils/resources'
```

`_`, `$` e `jQuery` são injetados pelo Vite em `src/**`, exceto em `src/routers/**`. Não importe
lodash.

## SyncStore

```js
const syncStore = useSyncStore()

await syncStore.fetchSync({
  app: 'arq',
  model: 'draft',
  params: { o: 'descricao' }
})

const item = computed(() => syncStore.data_cache?.arq_draft?.[props.id] || null)
const list = computed(() => Object.values(syncStore.data_cache?.arq_draft || {}))
```

`fetchSync({ app, model, id, action, params, only_first_page = false, force_fetch = true })`:

- Registra o model automaticamente, o que habilita as atualizações por WebSocket.
- Em listagens, usa `page: 1` e `o: 'id'` como padrão e percorre todas as páginas, salvo com
  `only_first_page: true`.
- Com `force_fetch: false`, devolve o que já estiver em cache.
- A chave do cache é `<app>_<model>`, indexada por `id`.

Mensagens `post_save` e `post_delete` recebidas por WebSocket atualizam o cache dos models
registrados. Outras ações úteis: `initialize`, `sendSyncMessage`, `invalidateDataCache`.

## AuthStore e MessageStore

```js
const authStore = useAuthStore()
authStore.isAuthenticated
authStore.hasPermission('arq.change_draft')

const messageStore = useMessageStore()
messageStore.addMessage({ type: 'success', text: 'Salvo.', timeout: 5000 })
```

`type` vira a classe `alert-<type>`, e sem `timeout` a mensagem não some sozinha.

## HTTP

Prefira `fetchSync` para dados que ficam em cache. Para os demais casos, use `Resources.Utils`, que
recebe sempre um objeto e monta URLs em `/api/<app>/<model>/`:

```js
Resources.Utils.fetch({ app: 'arq', model: 'arqdoc', query_string: 'o=-data&page=1' })
Resources.Utils.fetch({ app: 'arq', model: 'arqclasse', id, action: 'minha_acao' })
Resources.Utils.postModel({ app: 'arq', model: 'draft', form: { descricao: 'Novo' } })
Resources.Utils.patchModel({ app: 'arq', model: 'draft', id, form })
Resources.Utils.putModel({ app: 'arq', model: 'draft', id, form })
Resources.Utils.deleteModel({ app: 'arq', model: 'draft', id })
```

`fetch` aceita `params` no lugar de `query_string`. `postModel`, `patchModel` e `putModel` aceitam
`action` e `progress`.

## EventBus

```js
const EventBus = inject('EventBus')

onMounted(() => EventBus.on('side:close-sideleft', handler))
onUnmounted(() => EventBus.off('side:close-sideleft', handler))
```

## Rotas e módulos

Coloque telas novas em `src/modules/<modulo>/` e registre a rota em `src/routers/index.js`, com
`component: () => import('~@/modules/...')`. Os módulos principais ficam sob `/v6`.

## Lint e build

- `npm run lint` executa `eslint src/ --fix` e altera arquivos.
- `npm run format` executa `prettier --write src/` e altera arquivos. Rode só com pedido, para não
  reformatar componentes existentes.
- O Prettier usa sem ponto e vírgula, aspas simples e `arrowParens: avoid`.
- `npm run build` gera `dist/v6`, que é versionado. Rode só com pedido.
