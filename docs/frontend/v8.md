# Frontend v8

Frontend híbrido: o Django é dono das rotas e renderiza o que puder no servidor, e o Vue entra só
onde a página pede. O objetivo de longo prazo é substituir o v6 e o v2018. As regras estão em
`docs/specs/v8/`; este arquivo mostra como usar.

| Parte | Onde fica |
| --- | --- |
| App Django (rotas, views, tags, serviços) | `cmj/v8/` |
| Templates | `_templates/v8/base_v8.html` e `_templates/v8/v8/` |
| Frontend (Vue 3, Vite 8, Pinia, Reka UI, Tailwind v4) | `_frontend/v8/` |

Tudo o que o v8 cria responde em `/v8/...`.

## Qual modo usar

| Tipo de tela | Modo | Como |
| --- | --- | --- |
| Listagem, detalhe ou formulário que o Django já sabe renderizar | Página Django | View em `cmj/v8/views.py` e template que estende um layout, em geral `v8/layouts/app_sidebar.html` |
| A mesma tela com um trecho interativo (tabela com seleção, gráfico, editor) | Página Django com ilha | `{% v8_island %}` no template e componente no registro de ilhas |
| Detalhe ou ajuda que abre ao lado, sem sair da página | Drawer com fragmento ou painel | `data-drawer` no link; conteúdo em `/v8/_frag/` ou no registro de painéis |
| Tela com muita navegação interna e estado no navegador | Zona SPA | Zona em `s_global.ZONAS` e módulo de rotas no registro de zonas |
| Capa, página institucional | Página Django | Template que estende `v8/layouts/landing.html` |
| Login, erro, página sem moldura | Página Django | Template que estende `v8/layouts/minimal.html` |

Na dúvida, comece pela página Django e acrescente ilhas. Zona SPA só quando a tela for de fato um
aplicativo dentro da página.

## Templates em camadas

As regras estão em `docs/specs/v8/templates.md`. São três níveis, e cada um só estende o de cima:

```text
base_v8.html                     nível 1: esqueleto do documento, Vite e dados globais
├─ v8/layouts/minimal.html       nível 2
└─ v8/layouts/_shell.html        nível 2, abstrato: nenhuma página o estende
   ├─ v8/layouts/landing.html
   ├─ v8/layouts/app_topbar.html
   └─ v8/layouts/app_sidebar.html
      └─ a sua página            nível 3
```

| Layout | Para quê | O que tem |
| --- | --- | --- |
| `app_sidebar` | Telas operacionais | Barra lateral à esquerda com o menu, trilha, área de trabalho fluida |
| `app_topbar` | Funcionalidades com navegação superior | Menu na horizontal, trilha, conteúdo centralizado |
| `landing` | Capa e páginas institucionais | Menu na horizontal, `hero` de largura total, rodapé; sem trilha |
| `minimal` | Login, erro, telas de foco | Só o `<main>`, centralizado |

A página escolhe o layout no `extends` e preenche blocks. Ela nunca estende `_shell.html` nem
`base_v8.html`, e não sobrescreve `layout`, `html_attrs` nem `layout_name`.

| Block | Onde existe | Uso |
| --- | --- | --- |
| `content` | Nos quatro layouts | O conteúdo da página |
| `messages` | Nos quatro layouts | Mensagens do Django para quem está sem JavaScript; já vem preenchido |
| `title`, `meta`, `page_data`, `assets`, `scripts`, `body_class` | Na base | Título, SEO, `json_script` da página, entradas extras do Vite no `<head>` e no fim do `<body>`, classe do `<body>` |
| `header_start`, `brand`, `header_nav`, `header_actions`, `user` | Layouts com shell | Partes do cabeçalho, da esquerda para a direita |
| `aside`, `breadcrumbs`, `hero`, `footer` | Layouts com shell | Lateral, trilha, faixa antes do conteúdo e rodapé |
| `menu` | Layouts com shell | O menu principal, dentro de `aside` ou de `header_nav` |
| `footer_nav`, `footer_info` | `landing` | Colunas do rodapé, vazias no layout |

- Uma página que só preenche `content` funciona em qualquer um dos quatro layouts.
- `{{ block.super }}` mantém o conteúdo padrão de um block e acrescenta o seu.
- Use `{% include %}` só dentro de um block.
- O `hero` nasce vazio: a página escreve o próprio `<section class="v8-hero">`, com um
  `<div class="v8-hero-miolo">` para alinhar com o conteúdo.
- Layout novo estende `_shell.html`, sobrescreve só blocks de região e informa o nome em
  `layout_name`. O nome entra em `s_global.LAYOUTS`, e o CSS o distingue por
  `[data-v8-layout="<nome>"]`.

## Lado Django

### Página

```python
# cmj/v8/views.py
class RelatorioView(PaginaV8View):
    exige = "norma.view_normajuridica"   # None, s_global.AUTENTICADO, s_global.SUPERUSUARIO ou permissão

    def get(self, request):
        return responder_pagina(
            request,
            "v8/relatorios/lista.html",
            dados_layout("Relatórios", "relatorios", [("Início", "/v8/"), ("Relatórios", None)]),
            {"itens": s_relatorios.listar(request.user)},
        )
```

`dados_layout(titulo, menu_ativo, trilha, zona, tema)` monta a variável `v8`, a única que os layouts
leem. `tema` só se usa na prévia de um tema (veja "Design system e temas").
O `titulo` vira o `<title>` da página, seguido de "· PortalCMJ".
`PaginaV8View` só aceita `GET` e `HEAD`. Sem acesso, a navegação comum é levada ao login ou recebe a
página 403, e a requisição do cliente HTTP recebe 401 ou 403 em JSON.

```django
{% extends "v8/layouts/app_sidebar.html" %}
{% load v8_tags %}
{% block content %}
  <h1 class="v8-pagina-titulo">Relatórios</h1>
  ...
{% endblock %}
```

- A rota vai em `cmj/v8/urls.py`, começa com `^v8/` e termina com `/`.
- A regra de negócio fica em `cmj/v8/services/s_*.py`, que recebe o usuário por parâmetro.
- Template novo vai em `_templates/v8/v8/` e é referido como `v8/...`. **Nunca crie arquivo na raiz
  de `_templates/v8/`**: essa pasta é consultada antes de `_templates/v2018`, e um `base.html` ali
  encobriria o do portal.
- Layouts e blocks: veja "Templates em camadas", acima.
- Item de menu: `ItemMenu` na árvore de `cmj/v8/services/s_menu.py`, com a permissão exigida. Ao
  mudar a árvore, some 1 a `VERSAO_MENU`, que faz parte da chave do cache.

### Tags (`{% load v8_tags %}`)

| Tag | Emite |
| --- | --- |
| `{% v8_dados_globais %}` | `<script id="v8-global">` com usuário, permissões, URLs, zonas, modo e sidebar. Já está em `base_v8.html` |
| `{% v8_mensagens %}` | `<script id="v8-messages">` com as mensagens do Django, que viram toasts. Já está em `base_v8.html` |
| `{% v8_island "nome" props %}...{% endv8_island %}` | Elemento da ilha, `json_script` das props e o HTML de espera |
| `{% v8_preferencias as pref %}` | Tema, modo (claro ou escuro) e estado da sidebar, dos cookies `v8_tema`, `v8_modo` e `v8_sidebar`, só com valores válidos |
| `{% v8_menu as itens %}`, `{% v8_menu_chave as chave %}`, `{% v8_menu_versao as versao %}` | Menu do usuário e as partes da chave de cache dele |
| `{% v8_usuario as usuario %}` | Dados do usuário para a topbar (`id`, `username`, `nome`, `avatar`), ou vazio para anônimo |

Dado do servidor só chega ao JavaScript por `json_script`. Não escreva `<script>` com valor
interpolado.

### Ilha

```django
{% v8_island "clientes-tabela" props %}
  <table class="v8-tabela">...a tabela renderizada pelo Django...</table>
{% endv8_island %}
```

```js
// _frontend/v8/src/core/ilhas.js
export const ilhas = {
  'clientes-tabela': () => import('~@/modules/clientes/ilhas/ClientesTabela.vue')
}
```

O componente recebe as chaves de `props` como props. O HTML dentro da tag fica na tela até o
componente carregar, e continua sendo a tela se o JavaScript falhar.

### Gatilhos em HTML

Funcionam em qualquer HTML do v8, inclusive dentro de fragmentos, sem escrever JavaScript. Sem
JavaScript, o link ou o formulário segue o caminho normal, então o `href` deve levar a uma página
com o mesmo conteúdo.

| Atributo | Efeito |
| --- | --- |
| `data-drawer="cliente:42"` | Drawer do registro de painéis, guardado em `?painel=cliente:42` |
| `data-drawer="frag:demo/cliente/42/historico"` | Drawer com o fragmento `/v8/_frag/demo/cliente/42/historico/`, também em `?painel=` |
| `data-drawer="el:#filtros"` | Drawer com um elemento que já está na página; ele volta ao lugar ao fechar |
| `data-drawer-side`, `-size`, `-mode`, `-mode-estreito`, `-title`, `-scrim` | `left`/`right`; `sm`/`md`/`lg` ou medida CSS; `overlay`/`push`/`docked`; modo em tela estreita; título; `false` tira o fundo |
| `data-drawer-auto` (no próprio elemento, com `id`) | Em tela larga, o elemento abre sozinho como drawer, com as opções dele |
| `data-modal="nome:arg"` ou `data-modal="frag:caminho"` | Modal do registro de modals, ou com um fragmento |
| `data-confirm="Mensagem"` | Pede confirmação antes de seguir o link ou enviar o formulário |
| `data-confirm-title`, `-ok`, `-cancel`, `-variant="perigo"` | Textos e aparência da confirmação |

`data-confirm` não protege nada: a ação precisa ser `POST` com CSRF e validada no servidor.

### Fragmento

```python
class DemoClienteHistoricoFragmento(FragmentoV8View):
    exige = s_global.SUPERUSUARIO
    template_name = "v8/partials/demo/cliente_historico.html"

    def get(self, request, pk):
        cliente = _cliente_ou_404(pk)
        return self.responder_fragmento({"cliente": cliente, "eventos": s_demo.historico(cliente["id"])})
```

O template devolve só o trecho, sem layout. O texto de `[data-overlay-title]` vira o título do
drawer. A rota fica sob `^v8/_frag/`, e a view confere a permissão por conta própria: abrir a URL
direto dá o mesmo resultado que abrir pelo drawer.

### Zona SPA

```python
# cmj/v8/services/s_global.py
ZONAS = {"demo-spa": Zona("demo-spa", "demo/spa", "Demonstração SPA", "demo-spa", SUPERUSUARIO)}
```

A rota da zona responde ao prefixo e a qualquer subcaminho com a página `v8/paginas/zona.html`. O
prefixo é declarado só aqui: o frontend o lê de `#v8-global`. A zona usa o layout `app_sidebar`;
para outro, informe `layout="app_topbar"` (um dos nomes de `s_global.LAYOUTS`).

## Lado Vue

### Estrutura de `_frontend/v8/src/`

| Caminho | Conteúdo |
| --- | --- |
| `main.js` | Único entry: carrega o CSS e chama o boot |
| `App.vue` | Raiz do app único: ilhas, zona, overlays e toasts |
| `core/` | Boot, router, registros (`ilhas.js`, `zonas.js`, `paineis.js`, `modais.js`), gatilhos em HTML, shell, cookies |
| `overlays/` | Pilha (`OverlayStore`), moldura (`OverlayFrame`), `Drawer`, modals padrão, toasts e composables |
| `http/` | Cliente HTTP, `HttpError` e o fluxo de sessão expirada |
| `stores/` | `GlobalStore`, `AuthStore`, `SyncStore` |
| `componentes/` | Componentes base sobre o Reka UI, um por primitiva com visual (a lista está em `docs/specs/v8/componentes.md`), mais `datas.js` (conversão das datas) e `icones.js` |
| `modules/<app>/` | Telas: ilhas, painéis, modals e zonas de cada módulo; `modules/ds/` é a vitrine do design system |
| `css/` | `app.css` e uma pasta por tema em `temas/<nome>/` (veja "Design system e temas") |
| `utils/` | `resources`, `ws/WebSocketManager.js`, `timer/TimerWorkerService.js`, `EventBus.js` |

A página tem um app Vue, um Pinia e um router. O app é montado em `#cmj-v8-app`, que o Django
entrega vazio, e alcança o resto da página por `<Teleport>`. O HTML do Django nunca é compilado
como template Vue: não existem `[[ ]]` nem tags de componente em template Django.

### Componentes

`<script setup>`, JavaScript, com as seções `// 1. Imports` a `// 8. Functions`, nessa ordem. `_`
(lodash) é global em `src/**`; não existem `$` nem jQuery. Para usar um store fora de um componente,
passe o Pinia único: `useGlobalStore(pinia)`, com `import pinia from '~@/core/pinia'`.

```js
import { useGlobalStore } from '~@/stores/GlobalStore'   // dados de #v8-global
import { useAuthStore } from '~@/stores/AuthStore'       // isAuthenticated, hasPermission(perm)
import { useSyncStore } from '~@/stores/SyncStore'       // abre o WebSocket no primeiro uso
```

As permissões no navegador servem só para esconder o que o servidor recusaria.

### Rotas da zona

```js
// _frontend/v8/src/core/zonas.js
export const zonas = { 'demo-spa': () => import('~@/modules/demo/zona') }

// _frontend/v8/src/modules/demo/zona.js
export default {
  layout: DemoSpaLayout,                      // contém um <RouterView />
  rotas: [
    { path: '', name: 'demo_spa_inicio', redirect: { name: 'demo_spa_clientes' } },
    {
      path: 'clientes', name: 'demo_spa_clientes', component: () => import('./spa/ClientesLista.vue'),
      meta: { breadcrumb: 'Clientes' },
      children: [{
        path: ':id(\\d+)', name: 'demo_spa_cliente', component: () => import('./spa/ClienteDetalhe.vue'),
        meta: { breadcrumb: 'Cliente', drawer: { side: 'right', size: 'md', title: 'Cliente' } }
      }]
    }
  ]
}
```

- Os caminhos são relativos ao prefixo da zona, e toda rota tem `name`.
- `meta.breadcrumb` acrescenta um nível à trilha do servidor.
- Para a rota filha abrir num drawer, ponha `<DrawerRota />` no componente da rota pai, no lugar
  do `<RouterView />`, e as opções em `meta.drawer`. Fechar o drawer leva à rota pai.
- Navegar para fora da zona é carga normal de página: use `<a href>`, não `<RouterLink>`.

### Drawers

```js
import { useDrawer } from '~@/overlays/useDrawer'
const { openDrawer, openPanel } = useDrawer()

openPanel('cliente:42')                                   // fica em ?painel=, volta com o botão voltar
openDrawer({ componente: () => import('./Ajuda.vue'), props: { tema: 'x' } }, { side: 'left', size: 'sm' })
openDrawer({ frag: 'demo/cliente/42/historico' })         // fragmento do Django
openDrawer({ el: 'filtros' }, { mode: 'docked', modeEstreito: 'overlay' })   // elemento da página
```

```vue
<Drawer v-model:open="aberto" side="right" size="md" title="Detalhes">
  ...conteúdo...
  <template #footer><button class="v8-btn" @click="aberto = false">Fechar</button></template>
</Drawer>
```

| Opção | Valores |
| --- | --- |
| `side` | `left`, `right` |
| `mode` | `overlay` (modal), `push` (desloca a página), `docked` (parte do layout) |
| `modeEstreito` | Modo em tela estreita, quando difere |
| `size` | `sm`, `md`, `lg` ou uma medida CSS |
| `scrim` | `false` tira o fundo escurecido |
| `title` | Título do cabeçalho |

Painel novo para `?painel=` e `data-drawer="nome:arg"`: uma entrada em `core/paineis.js`, com
`componente`, `props(arg)` e `opcoes`.

### Modals

```js
import { useModal } from '~@/overlays/useModal'
const { confirm, openModal, openForm, openWizard, openFullscreen } = useModal()

const ok = await confirm({ titulo: 'Arquivar', mensagem: 'Arquivar 3 clientes?', rotuloOk: 'Arquivar', variante: 'perigo' })
const dados = await openModal(() => import('./Escolha.vue'), { opcoes })   // undefined se for dispensado
const salvo = await openForm(() => import('./ClienteForm.vue'), { cliente }, { title: 'Editar cliente' })
await openFullscreen(() => import('./Resumo.vue'), { id })
const novo = await openWizard({ title: 'Novo cliente', passos, dados: {}, concluir: d => http.post(url, d) })
```

Dentro do componente aberto, em drawer ou modal:

```js
import { useOverlay } from '~@/overlays/useOverlay'
const { close, dismiss, setDirty, setTitle } = useOverlay()
close(valor)       // fecha e resolve a Promise com o valor
dismiss()          // fecha como ESC: pede confirmação se houver alteração
setDirty(true)     // liga a guarda de alterações não salvas
```

`<OverlayFooter>` leva os botões para o rodapé fixo do overlay.

Formulário com erros do Django:

```vue
<form :id="idForm" @submit.prevent="submeter">
  <ErrosGerais :mensagens="gerais" />
  <CampoForm v-slot="campo" rotulo="Nome" :erro="erroDe('nome')">
    <input :id="campo.id" v-model="valores.nome" class="v8-entrada"
      :aria-invalid="campo.invalido" :aria-describedby="campo.descritoPor">
  </CampoForm>
</form>
<OverlayFooter>
  <button type="submit" class="v8-btn v8-btn-primario" :form="idForm" :disabled="enviando">Salvar</button>
</OverlayFooter>
```

```js
const valores = reactive({ nome: props.cliente.nome })
const { erros, gerais, enviando, submeter, erroDe } = useFormModal({
  valores,
  enviar: dados => http.put(`/v8/demo/api/clientes/${props.cliente.id}/`, dados)
})
```

Erro de validação mantém o modal aberto, com cada mensagem junto ao campo. Sucesso fecha e resolve
com a resposta. Passos do wizard: `{ titulo, componente, validar(dados) }`; o componente recebe
`dados` (objeto reativo comum aos passos) e `erros`.

### Toasts

```js
import { useToast } from '~@/overlays/useToast'
const toast = useToast()
toast.success('Cliente salvo.')
toast.error(erro.mensagem)       // o de erro só some ao ser dispensado
```

`messages.success(request, "...")` no Django vira toast na página seguinte.

### Componentes base

Ficam em `src/componentes/`, sobre as primitivas do Reka UI, com o visual do tema em vigor. Recebem
os dados por props, devolvem o valor por `v-model` e não chamam o servidor. Regras em
`docs/specs/v8/componentes.md`.

```vue
<Abas v-model="aba" rotulo="Dados" :itens="[{ valor: 'geral', rotulo: 'Geral' }, { valor: 'anexos', rotulo: 'Anexos' }]">
  <template #geral>...</template>
  <template #anexos>...</template>
</Abas>
<Sanfona v-model="aberta" :itens="[{ valor: 'a', titulo: 'Tramitação' }]"><template #a>...</template></Sanfona>
<Dica texto="Excluir o registro"><button class="v8-btn v8-btn-icone">...</button></Dica>
<Popover titulo="Filtros">
  <template #gatilho><button class="v8-btn">Filtros</button></template>
  <template #default="{ fechar }">...</template>
</Popover>
<MenuSuspenso rotulo="Ações" :itens="[{ valor: 'editar', rotulo: 'Editar' }, { separador: true }, { valor: 'excluir', rotulo: 'Excluir', perigo: true }]" @selecionar="executar" />
<Selecao v-model="bairro" name="bairro" rotulo="Bairro" :opcoes="[{ valor: 'centro', rotulo: 'Centro' }]" />
<CaixaMarcacao v-model="aceito" name="aceito" rotulo="Aceito os termos" />
<GrupoOpcoes v-model="turno" name="turno" rotulo="Turno" :opcoes="turnos" orientacao="horizontal" />
<Chave v-model="avisar" name="avisar" rotulo="Avisar por e-mail" />
```

Há um componente para cada primitiva do Reka UI com visual próprio, em cinco grupos (base, campos,
navegação e estrutura, datas e horas, cor). A tabela completa, com a primitiva de cada um, está em
`docs/specs/v8/componentes.md`, e todos aparecem na vitrine `/v8/ds/`.

```vue
<CampoNumero v-model="valor" name="valor" :formato="{ style: 'currency', currency: 'BRL' }" />
<SelecaoBusca v-model="bairro" name="bairro" rotulo="Bairro" :opcoes="opcoes" />
<SeletorData v-model="data" name="data" rotulo="Data da sessão" />          <!-- '2026-11-22' -->
<SeletorPeriodo v-model="periodo" name="periodo" />                           <!-- { inicio, fim } -->
<CampoHora v-model="hora" name="hora" />                                      <!-- '14:30' -->
<SeletorMes v-model="competencia" name="competencia" />                       <!-- '2026-11' -->
<Paginacao v-model:page="pagina" :total="total" :por-pagina="20" />
<Arvore v-model="pasta" v-model:expanded="abertas" :itens="[{ valor, rotulo, filhos }]" />
<PaletaCores v-model="cor" name="cor" :opcoes="[{ valor: corDoToken, rotulo: 'Primária' }]" />
```

- Com `name` e dentro de um `<form>`, os componentes de valor entram no envio nativo. Datas vão em
  ISO, e período e intervalo em `<name>_inicio` e `<name>_fim`. O `Alternador` não entra (use
  `Chave` ou `CaixaMarcacao`).
- Datas e horas: o v-model é texto ISO (`AAAA-MM-DD`, `HH:MM`, `AAAA-MM`, `AAAA`), em pt-BR. A
  conversão para os objetos do Reka fica só em `src/componentes/datas.js`.
- Cor: o v-model é hexadecimal. Não escreva cor no código: leia dos tokens, como a ilha `ds-cor`.
- O conteúdo flutuante (dicas, popovers, menus, seleções, calendários dos seletores, cartão
  flutuante) vai para o `body`, na camada `--z-popover`, e funciona dentro de drawers e modals.
- Os textos que o Reka traz em inglês saem em português; num componente novo, passe `aria-label`
  e `aria-roledescription` em português nas partes que os trazem.
- CSS de cada grupo em `css/temas/oficial/`: `primitivos.css`, `campos.css`, `estrutura.css`,
  `datas.css` e `cor.css`.
- Componente novo: o arquivo em `src/componentes/`, o CSS no grupo dele e a amostra na ilha do
  grupo, em `src/modules/ds/ilhas/`.

### HTTP

```js
import http, { HttpError } from '~@/http/client'

const lista = await http.get('/v8/demo/api/clientes/', { params: { q: 'ana' } })
await http.post(url, { nome: 'Ana' })        // também put, patch e delete
const html = await http.get('/v8/_frag/demo/ajuda/', { accept: 'html' })

try {
  await http.put(url, dados)
} catch (erro) {
  if (erro instanceof HttpError && erro.codigo === 'validacao') {
    erro.campos    // { email: ['E-mail já usado.'] }
    erro.gerais    // ['Situação inativa exige motivo.']
  }
}
```

- Endpoint JSON do v8 herda de `JsonV8View`, que responde 401, 403 e 404 sempre em JSON.
- É o único lugar que chama `fetch`. Envia o CSRF do cookie, recusa URL de outra origem e entrega
  todo erro como `HttpError`, com `codigo` em `validacao`, `nao_autenticado`, `sem_permissao`,
  `nao_encontrado`, `conflito`, `servidor`, `rede` ou `cancelada`.
- Sessão expirada no meio do uso abre um modal que leva à tela `/login/` em outra aba e refaz as
  requisições pendentes quando a sessão volta.
- `Resources.Utils` continua disponível para a API de models (`fetch`, `postModel`, `patchModel`...).
- Endpoint do v8 responde erro de validação com 400 e `{"detail", "errors", "non_field_errors"}`,
  montado por `s_respostas.erro_validacao(form)`.

### CSS

- Tailwind v4, lendo as classes de `src/` e de `_templates/v8/`. A paleta padrão foi retirada: só
  existem as cores semânticas, como `bg-superficie`, `text-texto`, `text-texto-suave`,
  `border-borda`, `bg-primaria`, `text-perigo`. As fontes (`font-sans`, `font-titulo`, `font-mono`)
  e os raios (`rounded-sm`, `rounded-md`, `rounded-lg`) também vêm dos tokens. Token sem utility
  própria entra por variável: `bg-(--cor-topo)`, `shadow-(--sombra-2)`.
- O CSS é o do tema oficial, em `css/temas/oficial/`: `tokens.css`, `elementos.css` (elementos HTML
  sem classe), `shell.css`, `componentes.css`, `overlays.css` e o CSS dos componentes base
  (`primitivos.css`, `campos.css`, `estrutura.css`, `datas.css`, `cor.css`).
- Classes de componente em `css/temas/oficial/componentes.css`: `v8-btn` (`-primario`, `-perigo`,
  `-fantasma`, `-icone`), `v8-campo`, `v8-rotulo`, `v8-entrada`, `v8-erro-campo`, `v8-alerta`,
  `v8-tabela`, `v8-cartao`, `v8-etiqueta`, `v8-paginacao`, `v8-barra-acoes`, `v8-lista-dados`.
- Cor literal só no `tokens.css` de um tema. Fonte, sombra e raio só por token (`--fonte-*`,
  `--sombra-*`, `--raio*`). Camadas e movimento só no `tokens.css` do oficial: `--z-base`,
  `--z-sticky`, `--z-drawer`, `--z-modal`, `--z-toast`, `--z-popover`; em classe, `z-(--z-toast)`.
- Layout: o elemento raiz traz `data-v8-layout="<nome>"`. Regra própria de um layout usa esse
  atributo, como em `[data-v8-layout="app_topbar"] .v8-conteudo`. A largura do conteúdo centralizado
  é o token `--largura-conteudo`.
- Modo: `<html data-modo="claro|escuro">`, vindo do cookie `v8_modo`. Sem cookie, vale a
  preferência do sistema. Cada cor tem valor no claro, no escuro e no bloco sem modo.
- Elemento HTML sem classe só recebe o estilo do tema dentro do conteúdo da página e do corpo dos
  overlays. Com classe, o estilo é o da classe.
- Classe nova em template Django só aparece em produção depois do rebuild.

## Design system e temas

Tema é o design; modo é claro ou escuro, e todo tema tem os dois. Regras em
`docs/specs/v8/temas.md` e `docs/specs/v8/ds.md`.

| Rota | Conteúdo |
| --- | --- |
| `/v8/ds/` | A vitrine: cores, tokens, elementos HTML, classes `v8-*`, ícones, drawers, modals, toasts e componentes base, no tema em vigor |
| `/v8/ds/temas/` | Os temas do registro, com prévia e "Usar este tema" |
| `/v8/ds/temas/<nome>/` | A vitrine no tema `<nome>`, sem mudar a escolha do navegador |

Tudo exige superusuário. "Usar este tema" grava o cookie `v8_tema`, e todas as páginas do v8 passam
a abrir nesse tema naquele navegador. Sem escolha, vale o `oficial`. O Django emite
`<html data-tema="<nome>">` em toda página.

```text
css/
├─ app.css                 Tailwind, @source e um @import por tema, o oficial primeiro
└─ temas/
   ├─ oficial/             o CSS padrão do v8: index.css, tokens.css e os demais
   └─ <nome>/              index.css, tokens.css e, opcional, regras.css
```

Tema novo:

1. Pasta `css/temas/<nome>/` com `index.css`, que importa `./tokens.css` e, se houver, `./regras.css`.
2. `tokens.css` redefine só tokens que existem no oficial, sob `:root[data-tema="<nome>"]`. Cada cor
   redefinida aparece nos três blocos, para o valor de um modo não vazar para o outro:

   ```css
   :root[data-tema="azul"] { --cor-primaria: ...; --raio: 0.25rem; }
   :root[data-tema="azul"][data-modo="escuro"] { --cor-primaria: ...; }
   @media (prefers-color-scheme: dark) {
     :root[data-tema="azul"]:not([data-modo]) { --cor-primaria: ...; }
   }
   ```

3. `regras.css`, se o tema redesenhar componentes: tudo em `@layer temas { :root[data-tema="<nome>"] {
   ... } }`, só com classes que existem no oficial. A camada `temas` vence os componentes do
   oficial e perde para as utilities.
4. Uma linha em `app.css` (`@import "./temas/<nome>/index.css";`) e uma entrada em
   `s_global.TEMAS`, na mesma ordem. O nome tem minúsculas, dígitos e hífen e não é `claro` nem
   `escuro`.

Seção nova na vitrine: uma entrada em `s_ds.SECOES` e a parcial `v8/partials/ds/<id>.html`. Seção
que precisa de JavaScript usa uma ilha, com um aviso como conteúdo de espera.

## Testes, lint e build

```bash
python -m pytest cmj/v8                       # lado Django
cd _frontend/v8 && npm run test               # Vitest + jsdom
cd _frontend/v8 && npx eslint src tests       # sem alterar arquivos
```

- Cada teste aponta a regra da spec: `@pytest.mark.spec("V8-ARQ-012")` no pytest, e o ID no começo
  do nome no Vitest.
- Node 24 ou superior. `npm run dev` sobe o Vite em `0.0.0.0:5174`; o container `cmjfrontv8` faz
  isso sozinho.
- `npm run lint` e `npm run format` alteram arquivos.
- `npm run build` gera `dist/v8`, que é versionado. Rode só com pedido.

## Integração com o Django e PWA

- `cmj/settings/frontend.py`: `DJANGO_VITE["v8"]`, `PROJECT_DIR_FRONTEND_V8` e `DEV_V8PORT`.
- `DJANGO_VITE_DEV_MODE` vale para v6 e v8 juntos. Ligada (e com `DEBUG`), o Django aponta para os
  dev servers em 5173 e 5174, e o CSS é injetado pelo JavaScript. Desligada, lê
  `dist/v8/.vite/manifest.json`.
- A porta 5174 está fixa em `vite.config.js` e em `VITE_FRONTENDS` de `cmj/globalrules/views.py`.
- O service worker (`src/service-worker.js`, Workbox, só precache) é registrado em build de
  produção, em `/v8/service-worker.js`, atendida por `service_worker_proxy` de
  `cmj/globalrules/urls.py`. `/v8/manifest.json` é atendida pela view `manifest`.
