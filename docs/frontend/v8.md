# Frontend v8

Vue 3, Vite 8 e Pinia, em `_frontend/v8/`. Nasceu como cópia do v6 e foi esvaziado: ficou só a
infraestrutura (stores, HTTP, WebSocket, EventBus, PWA), sem Bootstrap, jQuery, módulos ou telas. O
Django entrega `_templates/v8/base_v8.html` em `/v8/<slug>`, e o Vue Router assume daí.

Hoje a única rota é o 404: qualquer endereço em `/v8/` mostra `views/Error404.vue`.

## Diferenças para o v6

| | v6 | v8 |
| --- | --- | --- |
| Vite / Pinia | 7 / 3 | 8 / 4 |
| UI | Bootstrap 5, bootstrap-vue-next, Font Awesome | nenhuma; `scss/styles.scss` está vazio |
| Globais injetados | `_`, `$`, `jQuery` | só `_` |
| Stores | `SyncStore`, `AuthStore`, `TeleportStore`, `MessageStore` | `SyncStore`, `AuthStore` |
| Telas | `src/modules/` e `src/components/` | só `src/views/Error404.vue` |
| Dev server | 5173, container `cmjfront2026` | 5174, container `cmjfrontv8` |
| `django_vite` | app `default` | app `v8` |

`stores/`, `utils/resources`, `utils/ws`, `utils/timer`, `utils/EventBus.js` e `service-worker.js`
têm o mesmo comportamento dos do v6; só diferem por ajustes de lint. O que `docs/frontend/v6.md`
diz sobre `fetchSync`, `data_cache`, `AuthStore`, `Resources.Utils` e EventBus vale aqui.

## Estrutura de `src/`

| Caminho | Conteúdo |
| --- | --- |
| `main.js` | Cria o app, configura o axios (CSRF, sem cache em GET), `provide('EventBus')`, registra o service worker |
| `App.vue` | Componente `cmj-app`: só um `<slot />`; inicia o `SyncStore` e consulta o login |
| `registerComponents.js` | `rootComponents` (`cmj-app`, `cmj-error-404`) e `globalComponents` (vazio) |
| `routers/index.js` | Rotas; hoje só o 404 |
| `views/` | `Error404.vue` |
| `stores/` | `SyncStore.js`, `AuthStore.js` |
| `utils/` | `resources`, `ws/WebSocketManager.js`, `timer/TimerWorkerService.js`, `EventBus.js` |
| `scss/styles.scss` | Estilos globais, importado em `main.js`; vazio |
| `assets/` | `publicDir` do Vite: brasão, ícones, `favicon.ico`, `manifest.json`, `robots.txt` |
| `service-worker.js` | Fonte do service worker (Workbox, só precache) |

## Integração com o Django

- `cmj/core/urls.py`: `^v8/(?P<slug>[^.]*)$` → `app_vue_view_v8` → `base_v8.html`. `/v8` sem barra
  e endereços com ponto não casam com a rota.
- `base_v8.html` carrega `{% vite_asset 'main.js' app='v8' %}` e monta o app em `#cmj-app-root`.
  O conteúdo de `<cmj-app>` vem do template Django e é compilado no navegador, por isso o alias
  `vue` aponta para `vue.esm-bundler.js`. Nesse HTML a interpolação do Vue usa `[[ ]]`, e os
  componentes disponíveis são os de `rootComponents` e `globalComponents`.
- Blocos do template: `html_class`, `head_content`, `body_class`, `root_body`, `main_content`
  (contém o `<router-view>`), `footer_content`, `extra_js`.
- `cmj/settings/frontend.py`: `DJANGO_VITE["v8"]`, `PROJECT_DIR_FRONTEND_V8` e `DEV_V8PORT`.
- `DJANGO_VITE_DEV_MODE` é uma variável só para v6 e v8. Ligada (e com `DEBUG`), o Django aponta
  para os dev servers em 5173 e 5174. Desligada, lê `dist/v8/.vite/manifest.json`, e mudanças em
  `src/` só aparecem depois de um build.
- A porta 5174 está fixa em `vite.config.js` e em `VITE_FRONTENDS` de `cmj/globalrules/views.py`.
  Mudar só `DEV_V8PORT` não basta.

## Componentes novos

Use `<script setup>` com a mesma ordem de seções do v6 (`// 1. Imports` a `// 8. Functions`);
`App.vue` já a segue. Não há biblioteca de UI nem resolver de componentes: importe cada componente
onde for usá-lo. Registre em `registerComponents.js` só o que precisa aparecer em template Django.

```js
import { useSyncStore } from '~@/stores/SyncStore'
import { useAuthStore } from '~@/stores/AuthStore'
import Resources from '~@/utils/resources'

const EventBus = inject('EventBus')
```

`_` é injetado pelo Vite em `src/**`, exceto em `src/routers/**`. Não importe lodash. `$` e
`jQuery` não existem no v8: o ESLint acusa `no-undef` e o uso falha no navegador.

## Rotas

`createWebHistory()` não tem base, então os caminhos partem de `/`. Para a primeira tela, siga o
desenho do v6: um filho `path: 'v8'` com o componente de layout, e as telas como filhos dele, em
lazy import.

```js
children: [
  {
    path: 'v8',
    name: 'app_vue_v8',
    component: () => import('~@/modules/root/RootPage.vue'),
    children: []
  },
  { path: ':pathMatch(.*)', name: 'error_404', component: () => import('~@/views/Error404.vue') }
]
```

`src/modules/` ainda não existe; o caminho acima é o do v6, não um arquivo do v8.

## O que roda ao abrir a página

`App.vue` chama `syncStore.initialize()`, que abre o WebSocket `/ws/sync/` (ping a cada 30 s, até
10 tentativas de reconexão), e `authStore.loginStatus()`, que faz `GET /api/version`. Isso acontece
em toda página do v8, mesmo sem tela que use os dados.

## PWA

- O service worker é gerado pelo `vite-plugin-pwa` (`injectManifest`) a partir de
  `src/service-worker.js`, com escopo `/v8/`.
- `main.js` só o registra em build de produção, em `/v8/service-worker.js`. Essa URL é atendida por
  `service_worker_proxy` (`cmj/globalrules/urls.py`), que lê `dist/v8/service-worker.js` e envia
  `Service-Worker-Allowed: /v8/`.
- `/v8/manifest.json` é atendida pela view `manifest`, que lê `dist/v8/manifest.json`.
- Em produção o nginx serve `/static/v8/` (`docker/nginx/cmj_docker.conf`).

## Lint e build

- Node 24 ou superior (`engines` do `package.json`; o container usa `node:24`).
- `npm run dev` sobe o Vite em `0.0.0.0:5174`. O container `cmjfrontv8` roda `startfront-dev.sh`
  (`npm install` e `npm run dev`).
- O ESLint roda dentro do Vite só no dev server e apenas imprime os problemas no console: não
  interrompe o dev server nem entra no build. As opções `failOnError`, `emitWarning` e afins do
  `vite.config.js` não existem em `@nabla/vite-plugin-eslint` e são ignoradas.
- Regras: sem ponto e vírgula, aspas simples, sem vírgula final, sem espaço no fim da linha, no
  máximo uma linha em branco, mais `vue/strongly-recommended`. `eslint src/` passa sem erros.
- `npm run lint` (`eslint src/ --fix`) e `npm run format` (`prettier --write src/`) alteram
  arquivos.
- `npm run build` gera `dist/v8`, que é versionado. Rode só com pedido. O build de produção remove
  `console.log` e `console.debug`, e um passo final prefixa com `v8/` os caminhos de
  `dist/v8/.vite/manifest.json`, que é o que o `django_vite` lê.

## Restos do v6

Sobraram da cópia e não funcionam ou não são usados:

- `bootstrap` é global só para o ESLint. `main.js` executa `new bootstrap.Popover(...)` para cada
  elemento com `data-bs-toggle="popover"`; se algum template tiver esse atributo, a inicialização
  falha com `ReferenceError`.
- `EventBus` também é global só para o ESLint. Use `inject('EventBus')`.
- `src/sw.js` não é referenciado; o service worker vem de `src/service-worker.js`.
- `SyncStore` mantém a lógica de cronômetro do `painelset` (`startLocalCronometro`).
- `data-bs-theme="auto"` em `base_v8.html` e a regra `fortawesome` em `manualChunks`.

Remova cada resto junto com a mudança que deixar de precisar dele.
