# Frontend v2018

Vue 2, Vue CLI/Webpack, Vuex e BootstrapVue, em `_frontend/v2018/`. Está em **manutenção** e vai
continuar em uso a médio e longo prazo:

- Corrija bugs e faça ajustes sem migrar para Vue 3, Pinia ou Composition API.
- Não crie nele módulo nem entrada totalmente novos: isso vai para o v6 ou para o v8.
- Funcionalidade nova que complementa uma tela que já vive no v2018 pode ser feita nele quando for
  urgente e a migração da tela não couber no prazo. Onde ela entra (`src/modules` ou `src/__apps`)
  é decidido caso a caso: pergunte antes de criar.

A estrutura do projeto está especificada em `docs/specs/v2018/estrutura.md`, e a infraestrutura de
testes em `docs/specs/v2018/testes.md`.

## Integração com o Django

- `webpack_loader` carrega os bundles com `{% render_bundle %}`, como em
  `_templates/v2018/base.html` e `app_vue_v2018.html`.
- A rota `/app/<slug>` entrega `app_vue_v2018.html`.
- Além do bundle principal `app`, `vue.config.js` define as entradas `construct`, `compilacao`,
  `loa` e `libsuserauth`. Cada entrada é um módulo independente, com o próprio `main.js`, e só é
  carregada pelos templates que a pedem.
- `base.html` carrega `app` em toda página e `libsuserauth` só para usuário autenticado.
- Em dev, o Django usa `dev-webpack-stats.json` quando ele existe. Sem dev server ativo, esse
  arquivo deve ser removido.
- O HTML dentro de `<div id="app">` é compilado pelo Vue como template, com delimitadores `[[ ]]`.
  Ali o template Django só escreve tags de componente; variável só como id numérico em atributo,
  como `<app-pntp :classe_id="{{object.id}}">`. Nunca escreva texto vindo do banco ali dentro.

## Componentes

Use Options API. O alias é `@/`, e `_`, `$` e `jQuery` são globais.

```vue
<script>
import { EventBus } from '@/event-bus'

export default {
  name: 'MeuComponente',
  data () {
    return { itens: [] }
  },
  mounted () {
    EventBus.$on('meu-evento', this.onMessage)
  },
  beforeDestroy () {
    EventBus.$off('meu-evento', this.onMessage)
  },
  methods: {
    onMessage (data) {}
  }
}
</script>
```

Componentes do BootstrapVue (`<b-button>`, `<b-modal>`, `<b-table>`) estão registrados globalmente.
Para criar propriedade reativa em objeto existente, use `this.$set`.

## Mixin global

`src/mixins.js` já disponibiliza em todos os componentes, entre outros:

- Dados: `data_cache`, `user`, `permissions`, `cache`, `nivel_detalhe`.
- `utils`, que aponta para `Resources.Utils`.
- Ações: `sendMessage`, `refreshState`, `getObject`, `loginStatus`.

Verifique o mixin antes de repetir `mapState` ou `mapActions` em um componente.

O v2018 não tem WebSocket: as telas com atualização em tempo real estão no v6. `store__sync` é só
o cache dos dados buscados por HTTP.

## Vuex

| Módulo | Namespace | Conteúdo |
| --- | --- | --- |
| `store__sync` | Sim | `data_cache`, `fetchSync` |
| `store__auth` | Não | `data_connect`; getters `user`, `isAuthenticated`, `isVotante`, `permissions` |
| `store__message` | Não | `messages`; `getMessages`, `sendMessage`, `popMessage` |
| `store__online` | Não | `cache`, níveis de detalhe e estado dos painéis laterais |

Só `store__sync` aceita o namespace nos helpers. Não use `mapState('store__auth', ...)`.

```js
import { mapActions, mapGetters, mapState } from 'vuex'

computed: {
  ...mapState('store__sync', ['data_cache']),
  ...mapGetters(['user', 'permissions'])
},
methods: {
  ...mapActions('store__sync', ['fetchSync']),
  ...mapActions(['sendMessage'])
}
```

```js
this.fetchSync({ app: 'loa', model: 'orgao', query_string: 'o=id' })
this.data_cache.loa_orgao?.[42]
this.sendMessage({ alert: 'danger', message: 'Falha ao salvar.', time: 5 })
```

O formato da mensagem é diferente do v6: `alert`, `message` e `time` em segundos.

`fetchSync` aceita `app`, `model`, `id`, `action`, `params`, `query_string`, `only_first_page` e
`method`.

Ao contrário do v6, a maioria dos métodos usa argumentos posicionais:

```js
Resources.Utils.getModel(app, model, id)
Resources.Utils.getModelList(app, model, page, query_string)
Resources.Utils.getModelOrderedList(app, model, ordering, page, query_string)
Resources.Utils.getModelAction(app, model, id, action, query_string)
Resources.Utils.getModelListAction(app, model, action, page)
Resources.Utils.postModel(app, model, form)
Resources.Utils.postModelAction(app, model, id, action, form, progress)
Resources.Utils.patchModel(app, model, id, form)
Resources.Utils.patchModelAction(app, model, id, action, form, progress)

Resources.Utils.fetch({ app, model, id, action, params, query_string })
```

## Testes

```bash
cd _frontend/v2018
npm test              # roda tudo uma vez
npm run test:watch    # reexecuta ao salvar
npx vitest run tests/app/store.spec.js
```

Vitest com jsdom e `@vue/test-utils` 1 (a versão do Vue 2). Não precisa de dev server, backend nem
build. A configuração é `vitest.config.mjs`, separada do `vue.config.js`.

| Caminho | Conteúdo |
| --- | --- |
| `tests/setup.js` | O que o jsdom não tem, compilação de template em tempo de execução, bloqueio de rede |
| `tests/apoio.js` | `axiosFalso` e `esperar` |
| `tests/estrutura/` | Regras conferidas lendo arquivos (`vue.config.js`, templates) |
| `tests/app/` | Peças da entrada `app`: subida, store, mixin global, `Resources.Utils`, rotas |
| `tests/entradas/` | Subida das outras entradas |

- O teste que cobre uma regra de spec abre o título com o ID: `it('V2018-EST-033: ...')`.
- Todo teste que alcança HTTP começa com
  `vi.mock('axios', async () => (await import('../apoio')).axiosFalso())`. Requisição real falha.
- `$`, `jQuery` e `_` existem nos arquivos de `src/` como no build. No arquivo de teste, importe.
- `src/__globals` e a entrada `compilacao` não são importáveis nos testes: os plugins do jQuery UI
  dependem do carregador AMD do webpack. Para subir a entrada `app`, use
  `vi.mock('@/__globals', () => ({}))`.
- A entrada `construct` precisa do `tinymce` global: importe `@/__apps/libsuserauth/main` antes.
- Cada arquivo de teste tem o próprio cache de módulos. Um `main.js` só executa uma vez por arquivo.

## Lint e build

- `npm run lint` usa `vue-cli-service lint` e altera arquivos.
- `npm run build` gera `dist/v2018` e atualiza `webpack-stats.json`, ambos versionados. Rode só com
  pedido.
